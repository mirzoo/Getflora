# Iteration 5 QA Checklist

Цель: проверить Getflora как marketplace, а не как набор отдельных экранов.

## Подготовка

```bash
docker compose up -d
npm run dev
```

Открыть URL, который покажет Next.js.

## Основной A/B сценарий

- [x] Пользователь A входит по стабильному email.
- [x] Пользователь A создает объявление с несколькими фото URL.
- [x] Объявление видно в marketplace.
- [x] Объявление видно в `Мои объявления`.
- [x] У своего объявления нет добавления в избранное.
- [x] Пользователь A выходит.
- [x] Пользователь B входит по другому email.
- [x] Пользователь B видит объявление пользователя A.
- [x] Пользователь B добавляет объявление в избранное.
- [x] Пользователь B открывает объявление и нажимает `Купить`.
- [x] Открывается чат с продавцом.
- [x] Пользователь B отправляет сообщение.
- [x] Пользователь B выходит.
- [x] Пользователь A снова входит тем же email.
- [x] Пользователь A видит диалог и сообщение от B.
- [x] Пользователь A отмечает объявление как `Продано`.
- [x] Объявление исчезает из marketplace.
- [x] Объявление остается в `Мои объявления` со статусом `Продано`.

## Результат автоматического прогона

Дата: 2026-06-01.

Сценарий A/B пройден через браузерную проверку на `localhost`.

Найдено и исправлено:

- `Купить` открывал чат через `target="_blank"`, что ломало текущий сценарий
  проверки. Теперь чат открывается в текущей вкладке.

## Что считать багом

- Пользователь не может вернуться в тот же аккаунт по тому же email.
- Покупатель и продавец видят неправильные действия.
- Модалки открываются под другими модалками.
- Данные пропадают после refresh/sign out/sign in.
- Чат создается не с тем продавцом или не открывается.
- Своё объявление можно добавить в избранное.
- `Продано` не меняет видимость объявления.

## Проверки после исправлений

```bash
npm run typecheck
npm run lint
npm run build
```
