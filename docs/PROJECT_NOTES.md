# Project Notes

## Текущий статус

Основная backend/database итерация закрыта:

- Prisma + PostgreSQL foundation.
- Модели `User`, `Listing`, `ListingImage`, `Favorite`, `Conversation`, `Message`.
- Server-side repository/service слой для объявлений.
- Создание объявления сохраняет данные в PostgreSQL.
- Несколько фото объявления сохраняются как `ListingImage`.
- Избранное хранится в PostgreSQL.
- Сообщения и диалоги хранятся в PostgreSQL.
- Простая auth foundation через email/имя и httpOnly cookie.
- У каждого пользователя свои объявления, избранное и сообщения.

## Пользовательские сценарии

- Гость может смотреть маркетплейс.
- Для избранного, покупки, чата и публикации объявления нужен вход.
- Пользователь не может купить свое объявление.
- Покупатель открывает чат с продавцом объявления.
- Продавец видит покупателя в списке сообщений и внутри чата.

## Seller Workflow

Сверх базового плана добавлено управление объявлениями:

- Раздел `Мои объявления`.
- Кнопка `Продано`: статус `SOLD`, объявление исчезает из маркетплейса.
- Проданное объявление остается в `Мои объявления` 24 часа после `soldAt`.
- Кнопка `Снять`: статус `EXPIRED`, объявление сразу исчезает из маркетплейса и `Мои объявления`.
- Старые проданные объявления удаляются cleanup-логикой.

## Auth

Текущая авторизация намеренно простая:

- email + имя;
- httpOnly cookie `rebloom_user_id`;
- без паролей;
- без magic link;
- без внешних auth-провайдеров.

Это сделано для быстрого тестирования сценариев A/B до подключения настоящей
авторизации.

## Фото

Настоящая загрузка файлов пока не подключена. Сейчас форма принимает до 10 URL
фото, каждая ссылка сохраняется отдельной `ListingImage`.

Будущий production-вариант: S3-compatible storage.

## Cleanup

Есть два механизма:

- автоматический вызов при серверной загрузке главной;
- ручная команда `npm run db:cleanup`.

В будущем на VPS это лучше вынести в cron/background job.
